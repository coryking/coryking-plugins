# Workload usage accounting — issue #92

Implementation plan and product decisions for https://github.com/coryking/coryking-plugins/issues/92.

## Product contract

cc-explorer supplies evidence for workload economics. A consumer discovers sessions with existing tools, selects a workload, gets a compact accounting report, and drills into observations to audit a surprising number. A consultant can combine this with model evaluations and accepted-result artifacts to choose experiments. The MCP measures; it does not recommend models, infer successful outcomes, or maintain a pricing catalog.

The issue is the acceptance checklist except for the explicit scope decisions here: callers own all pricing. The primary use case is agent-dispatched workloads. Account across retained execution branches where the evidence supports it, deduplicating shared history; deleted or unrecorded usage cannot be reconstructed and must remain an explicit coverage gap. Cross-host federation, remote collection, shared stores, dashboards, new CLI surfaces, and a consultant skill are outside this implementation.

## Chosen interface

Add two read-only MCP tools, following the existing progressive-zoom approach:

- `get_usage_report`: select explicit sessions/agents or project scope and harnesses, optional half-open time window, descendant inclusion, optional caller-supplied attribution. Return scope, measured token totals, usage coverage, warnings, rollups and bounded session detail, in that order.
- `get_usage_observations`: inspect a session/agent's normalized observations with stable identity, source locators, category semantics, configuration and uncertainty. Bounded/paginated output, with counts and overflow guidance before detail. Reuse the report engine's observations, never recompute with a different algorithm.

Use existing project resolution, harness selectors and full session identities. Prefixes are input conveniences only, must resolve uniquely, and must never become accounting keys. Explicit selection must report or reject unresolved members; it must not silently omit them. Include the calling session when explicitly selected: measuring a running workload is legitimate. Do not inherit search's current-session exclusion blindly.

Default descendant inclusion makes a selected root useful; return the actual expanded membership and reasons. Explicitly selected children and discovered children count once. Independent sessions require explicit selection or declared corpus scope. Discoverable orphans remain visible and labeled; do not infer causal parentage from shared project or overlapping timestamps. A descendant outside a selected project is still part of an explicitly selected root's workload if discoverable, with its actual project preserved.

Prefer a small fixed set of useful rollups (session, model/effort, project, evidenced role, caller label) over a generic query language. Unknown configuration and attribution are explicit buckets. Caller attribution can label full session or observation identities with run/role/pass/round/phase and carry explicitly unit-labeled artifact measurements. Reject ambiguous or overlapping assignments that would multiply usage. No parsing arbitrary workflow files, byte-to-token conversion, or inferred accepted-result count. Raw IDs permit external joins without using the attribution option.

## Fit to the existing types

Read these first: providers/base.py (`ProviderSession`, `TranscriptProvider`), corpus.py (`Corpus`, `SessionRef`, `TranscriptSource`), models.py (`UsageInfo`, `TranscriptStats`, `UserOrigin`, tool/failure models), parser.py (typed records and diagnostics), providers/codex.py (rollout identity/lineage), subagents.py (relationships and conversion recognition), responses.py (typed MCP output).

Providers own format interpretation and physical-source discovery. Evolve their shared types/contract to supply typed accounting observations and coverage, with harness-specific implementations. Place common accounting models and arithmetic in focused modules; keep MCP functions thin. Do not build an unrelated discovery stack inside the MCP tools or force Codex counter events into fake assistant messages.

The transcript browsing view and execution accounting view can differ. Codex `_plan` cuts earlier rollouts at recorded history-base offsets and discovery selects a newest head. Expose evidenced history branches/cutoffs and multiple rollouts for one logical session where available, with source locators and timestamps when recorded. Do not call every history-base relationship a user revert: forked or inherited histories can also have lineage. Explicit revert markers may be labeled as such; weaker evidence stays labeled as lineage or a history cutoff. Follow retained execution branches when their identities and counter semantics permit accounting without double counting shared history. Deleted branches and unrecorded usage cannot be reconstructed. Affected accounting must state its observed-history scope and possible exclusions rather than assert a lifetime total. Inherited context in a child or fork is not newly incurred spend. Reuse provider discovery and preserve physical evidence separately from logical session identity; do not change browsing semantics to satisfy accounting.

`UsageInfo` defaults missing/null categories to zero and drops some provider detail. It cannot alone establish report completeness. Preserve field presence and native category semantics at ingestion. `TranscriptStats` currently sums assistant records and describes input as context size; it is not the accounting authority. Route existing accounting totals through shared corrected logic where applicable, or explicitly distinguish lightweight observed/context estimates from report-grade totals. Do not leave contradictory numbers advertised as equivalent. Attention bucketing remains separate from consumption accounting.

## Observation and coverage contract

An observation retains: harness-qualified full logical identity; execution/rollout identity where available; stable event/request identity or a documented fallback; all supporting physical source locators; event time; model and effort at the observation; native counter kind; measured token categories and inclusion relationships; derived accountable increment with attribution quality; context/input observation; evidenced lifecycle signals. Unknown values retain a machine-readable reason. Use explicit nullable/quality fields even though ordinary `SparseModel` responses omit nulls.

Do not hash content alone to merge distinct requests that happen to have identical counters. Do not key identity by file path, prefix, timestamp alone, or machine storing the file. Recorded execution host and account provenance are optional facts distinct from corpus root and storage host. Conflicting copies must be represented deterministically and excluded from an exact total unless reconciled by defensible evidence. Keep source evidence for all duplicates.

Claude request usage must reconcile streaming/multipart records sharing a request/message identity without counting each fragment. Nested subagent usage and parent dispatch summaries are not two charges. Preserve cache-write TTL categories and avoid charging aggregate cache-write tokens alongside their breakdown.

Codex repeated cumulative observations yield no additional consumption; they are not request counts. Derive deltas within justified execution/counter segments. Handle resets, missing observations, inconsistent category counters and mixed configurations explicitly. A gap spanning a configuration change cannot be assigned wholesale to the last model. Cumulative first observations may include earlier usage: keep the evidence and make time/configuration attribution uncertainty explicit. Read enough predecessor evidence for a time-window baseline; do not zero-baseline the first in-window cumulative counter. Never silently clamp a negative delta to zero and call the result exact.

A conversion's copied prefix is excluded from consumption. If a converted conversation is resumed, its new work is real consumption. Use conversion provenance to distinguish the two; if its boundary cannot be recovered, expose that limitation rather than dropping or charging the whole artifact. Distinct forks' newly executed requests remain distinct.

Report discovered/included/excluded/malformed/unreadable/missing-usage/conflicting source and session counts with reasons and clear denominators. Discovery failures that prevent enumerating a root are root-level uncertainty, not zero discovered sessions. Unsupported structural noise and malformed accounting evidence are different. Counts must survive parsing caches. Snapshot each source at a known observed size/boundary for a call; growing or truncated tails produce bounded observed results, not an assertion that the run is complete.

Keep model requests, assistant turns, human turns, injected user-role messages and tool invocations separately defined. Use existing user-origin and tool/failure classifications. A tool error does not establish a model retry or workflow failure. Request counts without sufficient request identity remain unavailable or explicitly a lower bound. Last assistant text is not proof of completion. Retain evidenced interruptions/retries/completion separately from usage.

Expose first/latest/peak observable input and subsequent observations, with their source semantics. First observable input is not necessarily the first prompt; request input is not necessarily exact current context occupancy. Separate elapsed transcript span, sum of session spans, overlap and evidenced active work; do not present summed child durations as wall-clock run time or apply arbitrary activity heuristics without labeling them.

## Pricing belongs to the caller

The MCP accepts no rates and calculates no currency amounts. Return model/configuration identity, token categories, recorded cache-write TTL/service-tier distinctions, inclusion relationships and uncertainty so a caller can apply its own rate source. Reasoning tokens included in output must not be added again; cache reads included in native input must be distinguished from uncached input. Preserve native and derived measurements so arithmetic is auditable. Missing categories remain unknown. The MCP neither estimates subscription allowance debits nor labels token usage as cash charged. Model selection, rates, pricing conditions, currency rounding and cost comparisons belong to the consuming consultant or application.

## Validation and delivery

Sol owns implementation and tests. Opus 5.5 at medium effort owns independent el-review; Sol resolves actionable findings. The planning agent does not write or review implementation code. Use synthetic fixtures and sanitized shapes, never publish personal transcript data. Verify wire semantics against authoritative upstream source/documentation where local fixtures do not establish them; preserve uncertainty for undocumented formats.

Mandatory invariant tests: duplicate requests/copies do not change totals; distinct identical-valued requests do; parent+child selection is idempotent; nested usage counted once; streaming fragments reconcile; conflicting copies remain visible; cumulative repeats add zero; resets/gaps/model transitions preserve attribution uncertainty; time windows use prior baselines; detectable history cutoffs/branches surface with honest accounting scope; inherited fork/conversion prefixes do not charge twice while new work does; category sums reconcile without reasoning/cache double counting; missing usage and malformed/unreadable roots affect coverage; live tails remain partial; pagination changes detail length but not totals; caller labels cannot multiply totals. Test MCP serialization, selectors and roundtrip drilldown alongside engine arithmetic.

Run the existing suite, targeted invariant tests and packaging checks. Update the self-contained cc-explorer skill with actual tool semantics and limitations; keep this document as design rationale rather than a second operational manual. Follow repository version/release bookkeeping. Commit and push on a codex/ branch. Delivery includes an independent Opus 5.5 agent at medium effort running el-review in report-only mode, Sol resolving findings (original builder or fresh agent), then verified merge, fleet deployment, issue closeout and end-session cleanup. Deployment must follow the authoritative fleet installation procedure and preserve unrelated work. Report acceptance coverage, test results and material limitations. Any genuine requirement gap remains explicit and the issue stays open until covered.

Cross-host assessment is limited to the boundary: reliable local identity/dedup is already necessary. Federation additionally needs root/host reachability coverage, account identity, consistent report snapshots and reconciliation across overlapping/conflicting corpora. It is materially more complex than summing host reports and belongs to #89/#88, with provenance dependencies tracked in #61. No fleet redesign in #92.
